# Cutu Circuits robotics

Native URDF XML is the source of truth. `parseUrdf(xml)` validates a connected tree with fixed, revolute, continuous and prismatic joints. Transforms follow URDF `Rz(yaw) Ry(pitch) Rx(roll)`; axes are in the joint frame. All values are SI metres, kilograms, seconds and radians; world gravity is along −Z. This boundary is independent of CAD/project millimetres.

`await createRobotSimulation(model, options)` creates a real Rapier 3D WASM world. Each link is a dynamic rigid body (optionally a fixed root), with physical impulse joints, gravity, frictional ground contacts and collision shapes. Authored center of mass and the full symmetric URDF inertia tensor are applied using its principal moments and principal frame. Mass must be positive; inertia must be positive definite and obey rigid-body triangle inequalities. Primitive boxes, spheres and Z-axis cylinders preserve collision origins. ASCII/binary STL collision meshes use convex hulls and an explicit async `meshResolver`; native STL and DAE visual meshes remain available to URDFLoader. Mesh resources can be URDF-relative (including `../`), percent-encoded local names, or ROS `package://pkg/path` references. The host resolver must enforce project filesystem confinement; the parser has no URDF path and cannot decide whether a relative resource stays inside the project. Linked parent/child collisions are disabled. Other self-collisions remain enabled.

The simulation exposes `step(count)`, `snapshot()`, `setJointTarget(name, position)`, `reset()` and `dispose()`. Snapshots contain simulation time, world link poses, physical joint positions, current targets and the number of near/touching contact points. Time advances only when the Rapier solver steps, using a fixed timestep (default 1/120 s). Reset reconstructs the original world, releases motors and resets time. Position motors use Rapier's acceleration model with stiffness 10,000 and damping 200 by default; options can change these gains. Targets clamp to physical URDF joint limits. Gravity and collisions can cause target error; targets and simulated position are separate.

Continuous joints are physically unconstrained about their axis; reported angles and position motor targets are periodic within one revolution. Multi-turn servo tracking is not modeled. Joint effort/velocity ratings, URDF friction/damping, texture materials and Gazebo/transmission extensions are explicitly diagnosed when present, and not applied as actuator/hardware models. Unsupported joint types, mimic/safety/calibration features, invalid numbers, malformed trees, absolute paths and remote/file mesh URLs fail validation. STL and DAE are the supported visual formats; OBJ is explicitly rejected. Collision physics requires primitive or STL geometry. DAE visuals with authored STL collisions simulate normally; a DAE-only link without supported collision geometry produces an explicit diagnostic and a simulation error before any world is built. URDF is capped at 1 MiB and 128 links; mesh reads cap at 500,000 triangles.

Missing inertia uses 1 kg and shape-derived inertia. Missing collisions fall back to visual geometry. Missing all geometry creates a mass-only body. Every such estimate is diagnosed. STL collision hulls lose concavity. Ground is a finite 100 × 100 m plane represented by a box, with friction 0.7. These are ideal rigid-body simulations, not measured robot behavior or certified dynamic models. There is no device control in this package.

Run `npx tsx --test packages/robotics/tests/*.test.ts` from the repository root. Tests exercise real free fall, ground contacts, authored joint transforms, fixed-base constraints, motor limits, STL hull collision, reset determinism, the arm template and Makada's authored visuals and contacts.
